# 记日子（AstrBot 插件）

让机器人对“时间”有感觉的 AstrBot 插件。主人在私聊里用 `/记日子` 记下生日、考试、纪念日，到了当天（考试、面试这类还有前一晚）机器人会主动发私聊提醒；同时插件会把“现在几点、距主人上一条消息过了多久”注入系统提示词，并在早上主人还没出现时主动道一句早安。

只对配置里的那一个主人 QQ 生效；所有主动消息都只发给主人私聊。

> 插件名 `astrbot_plugin_dafeiyu_dates` 是历史命名，功能与任何人设无关，可以配给任意 AstrBot 人设使用。

## 功能特性

- **记录重要日子**：主人私聊发 `/记日子 11-15 TOPIK考试`，记下日期、标题和“是否每年重复”。
- **当天主动提醒**：到日子的当天，时间过了 `morning_time`（默认 09:30）后，机器人按人设口吻主动发一条私聊祝福/加油。
- **考试类前一晚提醒**：标题里含考试、面试、比赛、答辩、手术、体检、出发、航班、报到、演出、上台等关键词时，前一天过了 `eve_time`（默认 21:30）再发一条打气消息。
- **一年一次 / 一次性**：标题前加“每年”就是每年重复（如生日、纪念日）；不加年份时默认记今年的日期，今年已过就自动算到明年；也可以显式写年份。
- **列表与删除**：`/日子` 查看所有记录和倒计时，`/删日子 编号` 删除。
- **去重发送**：每条提醒发送前先写“已发送”标记，进程重启也不会同一条重复发；已发送记录保留最近 500 条。
- **早上主动道早安**：`morning_greeting` 开启时，每天在 `morning_window`（默认 09:20-10:20）内一个固定随机时刻主动发早安，前提是主人当天 05:00 之后还没发过消息。
- **当天有日子就不重复道早安**：如果今天本来就要发日子提醒，当天不再单独发早安。
- **时间感注入**：`time_gap_hint` 开启时（默认），主人私聊的 LLM 请求会追加一行“现在几点、星期几”；距上一条消息超过 `time_gap_minutes`（默认 20 分钟）时再追加“隔了多久、他之前说的事多半做完了”的提示，避免机器人把一小时前说的“去吃饭”当成正在吃。
- **写进对话记录**：主动发送的消息会同时写入当前会话历史（若会话存在），主人回话时机器人知道自己刚说过什么。
- **模型失败兜底**：当天/前一晚提醒在全部模型都失败时，用内置的简短文案发送；早安如果模型失败则当天不发（不硬发固定句）。

## 适用场景 / 不适用场景

适合：

- 单主人、QQ 私聊为主的 AstrBot 实例。
- 希望机器人记住生日、考试、纪念日并主动关心。
- 希望机器人对时间有概念，不会把昨天的安排当成今天的。
- 希望早上收到一条主动的、像人设本人发出的早安。

不适合：

- 多人共享实例、需要给多个主人都记日子的场景（只认一个 `owner_qq`）。
- 群聊提醒、日历共享、复杂重复规则（插件只支持“每年”或“一次性”两种）。
- 完全离线的部署（主动消息需要模型；没配置模型时只有兜底文案）。
- 非 QQ 适配器（主动发送依赖 `FriendMessage` 的会话结构，其他平台未验证）。

## 工作原理

### 数据从哪来

- **日子**：全部来自主人在私聊里发的 `/记日子`，存在 `dates.json` 里，每条包含 `id`、`month`、`day`、`year`（`null` 表示每年）、`title`、`eve`（是否要前一晚提醒）。
- **时间感**：只记录“主人最近一次私聊的时间戳”和会话标识，存在 `last_seen.json`；不保存聊天内容。
- **已发送标记**：存在 `dates.json` 的 `sent` 列表里，形如 `3:2027-06-07:day`、`3:2027-06-07:eve`、`morning:2026-11-08`。

### 什么时候处理

插件启动后创建一个后台任务，每 60 秒检查一次：

1. 清理已经过去的一次性日子（`prune`）。
2. 读取所有日子，算出此刻该发的提醒：
   - 当天发生且当前时间 ≥ `morning_time` → 发“当天”提醒；
   - 明天发生、条目标记了 `eve`、当前时间 ≥ `eve_time` → 发“前一晚”提醒。
3. 每发一条前先写已发送标记，保证不会重复。
4. 如果开启 `morning_greeting`，再判断今天是否该道早安。
5. 睡 60 秒继续下一轮。

### 日期怎么算

- **每年**：月份/日期固定，找“今天及以后最近一次”的日期，2 月 29 日只在闰年出现，非闰年自动跳过。
- **一次性**：`year` 有值就按该年算；没写年份时按今年算，今年已过则算到明年；显式写了过去的年份会被拒绝（提示格式不对）。
- 日期合法性和闰年都会校验；非法日期（如 13 月 40 日）直接拒绝。
- 一次性日子过了之后会被后台任务自动删除，列表里不再显示。
- 全部按北京时间（UTC+8）计算，与服务器系统时区无关。

### 主动消息怎么发

- 会话标识：`adapter_id:FriendMessage:owner_qq`；`adapter_id` 留空时用 `last_seen.json` 里记录的主人最近一次私聊会话标识兜底。
- 文本生成：用 `persona_id` 对应人设的系统提示词（留空用插件内置中性文案），按顺序尝试 `provider_ids` 里的模型。
- 发送：`context.send_message(会话标识, 文本)`；随后尝试把“用户提示 + 机器人回复”写进当前会话历史，失败只记警告，不影响已发出的消息。
- 当天/前一晚消息的提示词要求 1～3 句、口语化、不要暴露“被提醒”、不编造主人没说过的细节；早安要求 1～2 句。

### 时间感怎么生效

1. 主人每发一条私聊消息，`track_owner` 记录时间戳（并保存会话标识）；若 `time_gap_hint` 为真，还会把“上一条时间、这一条时间”挂在事件上。
2. 同一条消息触发 LLM 请求时，`add_gap_hint` 把两段内容追加到系统提示词末尾：
   - `【现在】11月8日 星期六 20:15。说到时间就照这个说……`
   - 间隔 ≥ `time_gap_minutes` 时追加 `【时间】他上一条消息是……发的，现在是……，中间隔了 X 小时……`，并提示“聊天记录里他说正在做的事，按常理这会儿多半已经做完了”。
   - 跨天时再加一句“已经不是同一天了，不要接着昨天的情绪或安排往下说”。
3. 关掉 `time_gap_hint` 后，“现在几点”这行也不会注入（两者是同一个开关）。

### 数据存在哪

全部在 AstrBot 的插件数据目录下（代码通过 `StarTools.get_data_dir("astrbot_plugin_dafeiyu_dates")` 获取，AstrBot 4.x 通常位于 `<AstrBot 数据目录>/plugin_data/astrbot_plugin_dafeiyu_dates/`，以实际运行环境为准）：

```
astrbot_plugin_dafeiyu_dates/
  dates.json       # 日子列表、下一个编号、已发送标记
  last_seen.json   # 主人最近一次私聊的时间戳与会话标识
```

`dates.json` 结构示例：

```json
{
  "next_id": 3,
  "entries": [
    {"id": 1, "month": 3, "day": 8, "year": null, "title": "我生日", "eve": false},
    {"id": 2, "month": 6, "day": 7, "year": 2027, "title": "毕业答辩", "eve": true}
  ],
  "sent": ["1:2026-03-08:day"]
}
```

## 安装

前置：已部署 AstrBot（4.16.0 及以上），已配置 QQ 适配器（aiocqhttp），并已配置至少一个文本模型提供商。

### 方式一：AstrBot 插件市场

1. 打开 AstrBot 管理后台 → 插件市场。
2. 搜索 `astrbot_plugin_dafeiyu_dates` 或显示名“记日子”。
3. 安装后在插件管理页确认已启用。
4. 打开插件配置，填写 `owner_qq`、`provider_ids`。

### 方式二：后台上传 zip

1. 把本仓库根目录（含 `metadata.yaml` 的那一层）打包成 zip。
2. 后台 → 插件管理 → 上传/安装插件，选择 zip。
3. 确认安装后的目录名是 `astrbot_plugin_dafeiyu_dates`，再填配置。

> zip 内最好直接是插件文件；多包一层同名目录时以你实际后台的识别结果为准。

### 方式三：手动放到 data/plugins

1. 下载仓库代码。
2. 放到 AstrBot 的 `data/plugins/astrbot_plugin_dafeiyu_dates/`，目录名保持不变。
3. 重启 AstrBot，确认插件加载成功。
4. 后台插件配置里填写配置并保存。

## 配置项详解

字段与 `_conf_schema.json` 一一对应，可在 AstrBot 后台可视化修改。

| 配置项 | 类型 | 默认值 | 作用 | 注意事项 |
| --- | --- | --- | --- | --- |
| `owner_qq` | string | `""` | 主人 QQ 号 | 只接受这个号的私聊指令，主动消息只发给它。留空插件不工作。 |
| `adapter_id` | string | `""` | QQ 平台适配器实例 ID | 主动消息靠它拼 `适配器ID:FriendMessage:QQ`。留空时用主人最近一次私聊的会话标识兜底；主人首次私聊前无法主动发送。 |
| `persona_id` | string | `""` | 写消息用的人设 ID | 填 AstrBot 后台的人设 ID；留空用插件内置中性文案，不绑定具体人设。 |
| `provider_ids` | list | `[]` | 写消息用的模型提供商 ID，按顺序尝试 | 例如 `deepseek/deepseek-chat`。当天/前一晚提醒全部失败会用内置文案兜底；早安失败当天不发。 |
| `morning_time` | string | `"09:30"` | 当天提醒的发送时间（北京时间 HH:MM） | 到了之后才发；同一分钟粒度的后台检查可能晚几十秒。 |
| `eve_time` | string | `"21:30"` | 考试类前一晚提醒时间（北京时间 HH:MM） | 只对 `eve=true` 的条目生效。 |
| `time_gap_hint` | bool | `true` | 是否注入当前时间和时间差提示 | 关掉后“现在几点”那行也不再注入。 |
| `time_gap_minutes` | int | `20` | 间隔多少分钟以上才提示时间差 | 小于这个值只注入“现在几点”。 |
| `morning_greeting` | bool | `true` | 是否早上主动道早安 | 每天最多一次；当天有日子提醒时不另外道早安。 |
| `morning_window` | string | `"09:20-10:20"` | 早安时间范围（北京时间） | 格式 `HH:MM-HH:MM`；每天在范围内取一个固定时刻，重启不变。 |

配置示例：

```json
{
  "owner_qq": "123456789",
  "adapter_id": "",
  "persona_id": "",
  "provider_ids": ["deepseek/deepseek-chat"],
  "morning_time": "09:30",
  "eve_time": "21:30",
  "time_gap_hint": true,
  "time_gap_minutes": 20,
  "morning_greeting": true,
  "morning_window": "09:20-10:20"
}
```

## 使用方法

默认指令前缀是 `/`；如果改过 AstrBot 的指令前缀，请按改后的写。

### 记录日子

```
/记日子 11-15 TOPIK考试
/记日子 每年 03-08 我生日
/记日子 2027-06-07 毕业答辩
/记日子 2027年6月7日 毕业答辩
/记日子 6月7日 体检
```

- 日期和标题之间必须有一个空格；标题最多保留 40 字。
- 日期支持 `-`、`.`、`/`、`年`/`月`/`日` 分隔：`11-15`、`11.15`、`11/15`、`6月7日`、`2027-06-07`、`2027年6月7日` 都可以。
- 标题前加“每年”表示每年重复；写“每年”时即使带了年份也会被忽略。
- 不加年份：按今年算，今年已过就自动落到明年。
- 显式写过去的年份会被拒绝，按格式错误处理。
- 标题里含 `考`、`面试`、`比赛`、`答辩`、`手术`、`体检`、`出发`、`航班`、`报到`、`演出`、`上台` 任一关键词时，自动开启前一晚提醒。

成功后回复类似：`记下了：#3 2027 06-07 毕业答辩（还有 211 天）。到那天我来找你，前一天晚上我也会来给你打气。`

### 查看与删除

| 命令 | 作用 | 输出说明 |
| --- | --- | --- |
| `/日子` | 列出所有记着的日子 | 每条带编号、每年/年份、月日、标题、倒计时（“还有 N 天”“就是今天”“已过”）。 |
| `/删日子 2` | 删除编号 2 的日子 | 也接受 `/删日子 #2`；编号不存在会提示先发 `/日子` 看看。 |

### 自动行为

- 每天后台检查，到时间自动发当天提醒 / 前一晚提醒 / 早安。
- 主人私聊触发 LLM 时自动注入当前时间和时间差提示。
- 一次性日子过了之后自动从列表删除。

### 权限边界

- `/记日子`、`/日子`、`/删日子` 只对 `owner_qq` 本人、且必须是私聊生效；其他人发不回复、不处理。
- 其余 QQ 私聊和群聊也不会有任何响应。
- 主人发这几个命令时会终止事件继续传播（`event.stop_event()`），其他插件和默认对话不会再应答这条命令。
- 主动消息只发往 `owner_qq` 的私聊会话。

## 数据与隐私

- **存储位置**：AstrBot 插件数据目录（见“工作原理”）。`dates.json` 存你主动记的日子；`last_seen.json` 只存时间戳和会话标识。
- **不存聊天内容**：本插件不保存任何聊天正文，只保存“上一条消息的时间”和“主人私聊的会话标识”。
- **会外发什么**：生成提醒时，把“日期 + 标题”“现在时间”等拼进提示词发给你在 `provider_ids` 里配置的模型提供商，没有其他网络请求。
- **谁能看到**：本机插件数据目录的维护者；提醒只发给主人私聊。
- **保留多久**：日子一直保留到被删除或过期（一次性日子过期自动删）；已发送标记只保留最近 500 条。
- **怎么清空**：删 `dates.json` 即清空全部日子和发送记录；删 `last_seen.json` 即重置时间感。
- **备份**：备份这两个 JSON 文件即可。

## 依赖与前置条件

- **AstrBot**：`>=4.16.0`（见 `metadata.yaml`）。
- **平台适配器**：aiocqhttp（QQ）。插件按 `FriendMessage` 会话结构判断主人和发送消息，其他适配器未验证。
- **模型提供商**：主动消息质量依赖模型；不配置时当天/前一晚提醒用内置文案，早安不发。
- **Python 包**：没有额外第三方依赖，不需要 `pip install`（仓库不含 `requirements.txt`，仅用 AstrBot 自身依赖与标准库）。
- **权限**：AstrBot 进程需要对插件数据目录有写权限，并能访问配置的模型服务。

## 常见问题 FAQ

**1. 早上没收到早安？**

按顺序检查：`morning_greeting` 是否开启；`owner_qq` 是否填写；主人当天 05:00 后是否已经发过消息（发过就不发早安）；当前时间是否落在 `morning_window` 内；当天是否本来就有日子提醒（有就不另外道早安）；`provider_ids` 是否可用（模型失败当天不发）。

**2. 到了日子当天没收到提醒？**

检查 `owner_qq` 是否填对、是否在私聊；确认当前时间已过 `morning_time`；确认后台任务在跑（插件已启用）；看 AstrBot 日志里有没有 `[记日子]` 的警告。若当天是刚记录且已过发送时间，插件会标记为已发送，不会立刻补发，避免刚记完就弹消息。

**3. `adapter_id` 不知道填什么，不填行不行？**

可以留空。留空时用主人最近一次私聊的会话标识兜底；但如果主人从没私聊过，插件无法主动发送，会在日志里提示。填上 AstrBot 后台平台适配器页里的实例 ID 最稳。

**4. 记录日子的格式总提示错误？**

常见原因：日期和标题之间没有空格；月份/日期超出范围；用“每年”却写了非法日期；显式写了已经过去的年份。按 `/记日子 11-15 考试` 或 `/记日子 每年 03-08 生日` 的格式来。

**5. 考试前一晚没有提醒？**

检查标题里是否包含关键词（考试、面试、比赛、答辩、手术、体检、出发、航班、报到、演出、上台）；确认当前时间已过 `eve_time`；确认那天是“明天”。不包含关键词的日子只发当天提醒。

**6. 会不会同一条提醒发两次？**

不会。每条提醒发送前先写已发送标记（形如 `编号:日期:day/eve`），后台每 60 秒检查时跳过已发送的；重启后标记还在 `dates.json` 里。除非你手动删了 `dates.json`，否则不会重复。

**7. 每年生日是怎么算的？**

条目的 `year` 为 `null` 表示每年重复，插件找“今天及以后最近一次”的 3 月 8 日；2 月 29 日的生日只在闰年触发，非闰年会跳过。

**8. 一次性日子过了会怎样？**

后台检查发现它已经过期（下一次发生日期早于昨天）就自动删除，`/日子` 里不再显示；想留档就自己另存一份。

**9. 服务器时间不对，会影响提醒吗？**

不会。插件固定按 UTC+8 计算日期和 `morning_time`/`eve_time`/`morning_window`，与系统时区无关。

**10. 主动消息发出去后，机器人记得自己说过什么吗？**

会尝试把消息写进当前会话历史（`conversation_manager`）。如果当时没有当前会话（比如从没私聊过），只发消息、不写历史，日志会有警告。

## 兼容性

- **适配器**：只验证过 aiocqhttp 的 QQ 私聊。其他适配器会话标识不同，主人判断和主动发送都可能不生效。
- **其他插件**：插件把自己的事件附加字段命名为 `_owner_gap`、`_owner_seen`，命名空间加了下划线，一般不会与其他插件冲突；命令名 `/记日子`、`/日子`、`/删日子` 若与其他插件重名，AstrBot 会各自响应。
- **系统提示词注入**：只在主人私聊的 LLM 请求末尾追加内容，可与 AstrBot 人设、记忆类插件共存；如果同时装了其他“时间感”插件，可能出现重复提示。
- **与私人日记类插件共存**：两者都向系统提示词追加内容，一般互不影响，但上下文会更长。
- **AstrBot 版本**：依赖 `Star`、`StarTools`、`filter`、`ProviderRequest`、`conversation_manager` 等 4.x 接口；更老版本未验证。

### 测试

原插件没有自带测试，仓库里也没有 `tests/`。可以这样自检：

```powershell
py -m py_compile main.py dates_core.py
```

`dates_core.py` 是不依赖 AstrBot 的纯逻辑，适合自己补单元测试，重点覆盖：

- `parse_add`：各种日期写法、非法日期、过去年份、“每年”前缀、标题截断。
- `occurrence`：一次性过期、每年重复、2 月 29 日在非闰年的行为。
- `due`：当天提醒、前一晚提醒、时间未到、已发送集合去重。
- `morning_due`：时间窗口边界、当天 05:00 后已聊过、当天已发过。
- `gap_hint` / `now_line`：短间隔不提示、跨天提示。

### 改代码注意点

- `dates_core.py` 保持不 import AstrBot，方便单测；AstrBot 相关逻辑只放 `main.py`。
- 数据路径统一走 `StarTools.get_data_dir(PLUGIN)`，不要写死本机路径。
- 时间统一用 `CST`（UTC+8），不要混用系统时区。
- 发送前必须先 `mark_sent` 再发送，保持“绝不重复发”的语义。
- 改命令名、关键词、配置项时同步更新 README 和 `_conf_schema.json`。
- 不要在日志里打印聊天全文或任何密钥。
